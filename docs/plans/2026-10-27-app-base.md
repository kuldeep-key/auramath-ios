# Auramath App Base Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Set up the repo and the app base: Flutter project, design system from Figma, the pure Dart teaching engine, the offline event outbox, and one lemon-tree lesson playable end to end from Home on a sample pack.

**Architecture:** Flutter app at the repo root using Flutter's recommended layering (views + `ChangeNotifier` view models, repositories, services). All teaching decisions live in `packages/auramath_engine`, a pure Dart package with golden vectors and a checker CLI the backend can reuse. Every child input is an event saved to SQLite first and synced to a fake API with retry.

**Tech Stack:** Flutter 3.44.6 / Dart 3.12.2, `go_router`, `provider`, `sqflite` (+ `sqflite_common_ffi` for tests), `path_provider`, `flutter_tts`, `flutter_localizations` + `intl` (gen-l10n), `fake_async` (tests). Engine: no dependencies, `test` for dev.

**Spec:** `docs/architecture.md` (and `docs/decisions-to-confirm.md` for platform settings). Screen and behaviour details come from the prototype `../auramath-prototype-standalone.html` and the Figma page "Screens · Prototype copy (27 Oct)" (file `gZoJBnoM4LLNxK0YbYjKn3`, node `629:2`).

**Out of this plan (later plans):** setup and phones, free check, grown-up area and lock, trail and badges screens, detective and voice pick, other activities, pack download and signature check, audio clips, membership, notifications, the real API. In this plan the comparison activity is written in engine code driven by pack data (numbers, lines, hints, timers, next problems); turning activities into fully data-defined rules waits for the real content format from the backend.

## Global Constraints

- Application ID / bundle ID `net.auramath.app`; Dart package name `auramath`; display name `Auramath`.
- iOS deployment target 16.0; Android `minSdk` 26; iPhone only (`TARGETED_DEVICE_FAMILY = 1`); portrait only.
- English only; every UI string lives in `lib/l10n/app_en.arb`; lesson lines come from the pack.
- No third-party SDKs (no Firebase, analytics, crash reporting). No runtime font fetching. No AI calls.
- The child never sees a score, count, percentage or level number.
- `packages/auramath_engine` imports nothing from Flutter, `dart:io`, `dart:math` `Random`, or `DateTime.now()`. Same inputs, same outputs.
- Screens are laid out for 390 × 844. Each screen widget's doc comment names its Figma ID (e.g. `/// Figma: M0`).
- Colours, radii and type come only from `lib/ui/core/theme/`; no hex value appears outside it.
- Commits: conventional messages, no `Co-Authored-By` line (user's global rule). Work on branch `feat/app-base`. Never push.

## Review Focus

1. **App killed mid-lesson:** reopening the same session resumes at the same step with the same board. Pinned in Task 10 (`resume returns inputs in seq order`) and Task 11 (`view model restores step from outbox`).
2. **The same batch sent twice:** no duplicate rows. Pinned in Task 10 (`duplicate session_id+seq is ignored`).
3. **Keypad abuse** (empty Check, more than 4 digits, leading zeros): Check with nothing typed does nothing; a 5th digit is ignored; `007` is read as 7. Pinned in Task 8.
4. **Input in the wrong step** (double tap, a late drop, a number typed while drawing): the engine returns the same state and no decisions. Pinned in Task 3 (`input not valid for step is ignored`).
5. **A whole lesson offline:** events stay unsent, nothing is lost, and the next successful sync sends them all in seq order. Pinned in Task 10 (`offline lesson syncs in order later`).

### Task 3: Engine lesson flow (drawing, choosing the sum, answers)

**Files:**
- Create: `packages/auramath_engine/lib/src/lesson.dart` (state, inputs, decisions, `step`)
- Test: `packages/auramath_engine/test/lesson_flow_test.dart`

**Interfaces:**
- Consumes: Task 2 types.
- Produces:
  - `enum LessonStep { question, drawA, placeB, sizeB, placeGap, placeTotal, chooseOp, findB, findTotal, sideLesson, solved }`
  - `sealed class LessonInput` with: `Started()`, `BarADrawn()`, `BarBPlaced()`, `BarBSized(Relation rel)` (`enum Relation { taller, shorter, same }`), `PieceDropped(Piece piece, Target target)` (`enum Piece { gap, total }`, `enum Target { gapSlot, totalSlot, barA, barB }`), `OpChosen(Op op)` (`enum Op { add, subtract }`), `NumberEntered(int value)`, `SideLessonDone()`, `Undo()`
  - `sealed class Decision` with: `Coach(String lineId, Map<String, String> slots)`, `Wobble()`, `ShakeHelp()`, `OpenSideLesson(SideLesson kind)` (`enum SideLesson { takeAcrossTen, addWithCarry }`), `Solved(SolvedBy by, String badgeId, String nextProblemId)` (`enum SolvedBy { draw, know, partway }`)
  - `class LessonState` (immutable, `copyWith`, `==`): `step`, `barA`, `barB`, `gapPlaced`, `totalPlaced`, `op`, `wrong`, `wrongRow`, `findBWrong`, `hintsUsed`, `sideLessonRan`, `returnStep` (Task 4 adds `knowFlow`, Task 5 adds `quietLevel`)
  - `LessonState initialState()` → `step: question`
  - `({LessonState state, List<Decision> decisions}) step(Pack pack, ComparisonProblem p, LessonState s, LessonInput input)`
  - Slots every `Coach` carries: `a`, `b` (lower-case names), `B` (b name as written), `av`, `d`, `u`, `rel` (`shorter` when big a, else `taller`), plus `v` when a number is involved.

Rules (from the prototype's `checkB2`, `zoneFor`, `wrongMove`, `checkB`, `checkT`):
- `question` + `Started` → `drawA`. `drawA` + `BarADrawn` → `placeB`. `placeB` + `BarBPlaced` → `sizeB`.
- `sizeB` + `BarBSized`: right relation (`shorter` when big a, `taller` when big b) → `placeGap`, `wrongRow = 0`; `same` → `Coach('cmp.sizeB')`, no wrong count; wrong relation → wrong move with `Coach('cmp.sizeBWrong')`.
- `placeGap` + `PieceDropped(gap, gapSlot)` → `placeTotal` if ask total, else `chooseOp`; gap on a bar → wrong move with `Coach('cmp.gapWrong')`.
- `placeTotal` + `PieceDropped(total, totalSlot)` → `chooseOp`; total on a bar → wrong move with `Coach('cmp.totalWrong')`.
- `chooseOp` + `OpChosen`: subtract when big a / add when big b → `findB`; the other → wrong move with `Coach('cmp.opWrong')`.
- `findB` + `NumberEntered(v)`: `v == bValue` → `Coach('cmp.right', v)` then `findTotal` (ask total) or `Solved(draw, …)` (ask b). Else `findBWrong++` and route: regrouping → `Coach('cmp.regrouping')` + `OpenSideLesson(takeAcrossTen)`, step `sideLesson`, `returnStep: findB`; oppositeOp → wrong move `Coach('cmp.opposite')`; anything else → wrong move `Coach('cmp.tryAgain')`, and if `findBWrong >= 2` also `OpenSideLesson(takeAcrossTen)`.
- `findTotal` + `NumberEntered(v)`: `v == total` → `Solved(draw, …)`; `v == dropCarry(a, b)` → `Coach('cmp.carry')` + `OpenSideLesson(addWithCarry)`; `|v - total| <= 10` → wrong move `Coach('cmp.recheck')`; else wrong move `Coach('cmp.addBoth')`.
- `sideLesson` + `SideLessonDone` → `returnStep`.
- A wrong move = `wrong++`, `wrongRow++`, `Wobble()`; when `wrongRow >= 2` also `ShakeHelp()`. Any right board move resets `wrongRow` to 0.
- `Undo` steps the board back one step (`sizeB → placeB`, `placeGap → sizeB`, `placeTotal → placeGap`, `chooseOp →` previous placement step); ignored in other steps.
- Any input not listed for the current step returns the same state and no decisions.
- `Solved` badge and next problem: badge `asker` if `hintsUsed > 0` or a side lesson ran, else `tree`; next `p.next.fast` if `wrong == 0 && hintsUsed == 0`, else `p.next.helped`.
